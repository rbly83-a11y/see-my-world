## Notes on the labels

1. **"Specified" means specified on paper.** It asserts that a contract, schema, or normative rule exists in the baseline text. It asserts nothing about code, because there is none (`PROJECT_STATE_AUDIT.md` §3).
2. **"Concept" means a defined proposal** whose contracts or acceptance criteria are not yet specified to buildable depth — e.g. the Storyworld Engine, the Immersion Ladder, the Era Worlds pillar features.
3. **The five "Tested (reported)" features** (First Light owner journey; Lens and Perspective publication; Visitor journey and Seeds; Invitations; Comparison — all at Edition 1.1 scope) rest solely on reported v36.2/v36.3 simulation results (47/47 five-user; 56/56 20-user adversarial; runtime and protocol suites as reported at Ch. 35 §35.1). The v9.8 archive's 736/736 validation result belongs to a separate, earlier lineage and is not evidence for these features (Ch. 35). Until the v36 source is produced and inspected (gap E01, queue Q-20), "reported" is the strongest honest label.
4. **Meridian's ceiling is explicit:** the reference implementation is Specified *at specification freeze* — Continuation 30 §420 states the freeze is "not a claim that the application is already production-ready."
5. **Nothing in Parts XIV–XVIII (Edition 1.4's new material) exceeds Specified**, and the Living Memory Network's §§291–300 material is Concept *and* register-derived — the weakest-evidenced material in the baseline.
